# v1.1 — persistence fix and browser UI

Follows `docs/work-items/SPEC.md`. Everything here is TDD red→green at the
seams below. The existing JSON API (`/stories`, `/users`, `/p`, `/edit`, locks,
shares) must keep working unchanged.

## Slice 1 — Persist SQLite on the data volume

Seam: `create_app` config.

- Default `DATABASE` = `<DATA_DIR>/box_of_twine.sqlite`, derived after the test
  config is merged; an explicit `DATABASE` in the config still wins.
- Re-creating the app against the same `DATA_DIR` sees the same users and
  stories (i.e. a restart keeps data).
- Update the README/compose description so `/data` is documented as holding the
  story sources **and** the SQLite metadata.

## Slice 2 — Home page

Seam: `GET /`.

- Anonymous → 302 redirect to `/login`.
- Authenticated → 200 HTML listing the user's accessible stories (owned **and**
  shared-with-them) with a link to `/edit/<id>` for each, the current user's
  name, and a "New story" form (a `name` field posting to `/stories/new`).
- Template `home.html`; honour the stored theme like `login.html` does.

## Slice 3 — Create a story from the home form

Seam: `POST /stories/new`.

- Authenticated form POST with `name` creates a valid Twine story (Harlowe,
  with a `Start` passage and an ifid), writes its source and metadata row, then
  303-redirects to `/edit/<id>`.
- Anonymous → redirect to `/login`.
- The new story then appears on `GET /`.

## Slice 4 — Admin users page

Seam: `GET /admin/users`.

- Admin → 200 HTML listing every user with username, admin/disabled state, and
  the action forms needed by Slice 5.
- Anonymous → redirect `/login`; authenticated non-admin → 403.

## Slice 5 — Admin user actions

Seam: form POSTs.

- `POST /admin/users` — create (`username`, `password`, `is_admin`) → 303 to
  `/admin/users`.
- `POST /admin/users/<id>/update` — optional `password`; `disabled` and
  `is_admin` checkboxes → 303.
- `POST /admin/users/<id>/delete` — hard delete with the existing cascade → 303.
- All admin-only with the same auth rules as Slice 4. Refactor `users.py` so the
  JSON endpoints and these form handlers share one set of helpers (no duplicated
  user-mutation logic).
